# ARCHI LAW (아키로) — Claude Code 통합 개발 프롬프트 v1.1

> **현재 목표**: 개인용 건축법령 AI 검색기의 Phase 1 UI를 완성한다. **장기 목표**: 팀원들이 사용하는 견적/상담 등 별도 프로그램에서도 동일한 법령 검색 엔진과 AI 비용 관리 엔진을 호출할 수 있게 한다. 개인용 개발 단계에서 팀용 UI·인증까지 만들지는 않는다.
>
> **개발 모델**: 현재는 Claude Code **Sonnet** 사용. Opus로 자동 전환하지 말고, 반드시 필요한 이유와 작업 범위를 보고한 뒤 사용자에게 결정받는다.

## 0. 작업 전에 꼭 읽을 파일

1. `archilaw-apple-budget-ui.html` — **최신·최우선 디자인 원본** (이전 녹색/모노 HTML보다 우선)
2. `archilaw-budget-desktop.png`, `archilaw-budget-mobile.png`, `archilaw-budget-dark.png` — PC/모바일/다크 모드 기준 이미지
3. `CLAUDE_UI_BUDGET_GUIDE.md` — 모델 선택/토큰 비용/예산 관리 기존 규칙
4. `CLAUDE_UI_MONO_GUIDE.md` — 컴포넌트·시각적 일치/동작 검수 기존 규칙

문서 간 디자인 충돌이 발생하면 **최신 HTML의 실제 화면을 우선**한다. 이 프롬프트는 기존 가이드의 내용을 대체하는 것이 아니라, **향후 팀 프로그램 연동을 위한 구조적 제약**을 추가한다.

## 1. 제품 원칙 — 반드시 지킬 것

- 지금은 **사용자 1명만 사용하는 로컬 웹앱**. 회원가입, 팀 관리 대시보드, 클라우드 배포, 과금 결제 시스템을 지금 구현하지 않는다.
- 다만 처음부터 **UI / 건축법령 검색 서비스 / AI 공급자 호출 / 토큰·비용 관리 / 데이터 저장**을 분리한다.
- 나중에 견적·상담·리모델링용 팀 업무 프로그램에서 검색 서비스를 중복 개발하지 않고 연결할 수 있어야 한다.
- **MCP는 검색 도구 연결 규격**이며, 다른 프로그램과의 범용 연동용으로는 **버전 있는 내부 REST API 또는 타입이 명확한 서비스 인터페이스**를 기본으로 한다. MCP는 이 서비스의 어댑터로 붙일 수 있다.
- 팀 확장 가능성을 위해 과한 마이크로서비스, 도커 군집, 초기 로그인/권한 화면을 만들지 말 것. **모듈형 단일 백엔드(modular monolith) + 분리된 React UI**를 권장한다.
- 확정된 Apple-inspired UI(화이트/실버/차콜/절제된 블루)를 임의 변경하거나 녹색 스타일로 되돌리지 않는다.

## 2. 전체 아키텍처 기준 (설계만 먼저 확정)

```text
[아키로 개인용 React UI]               [미래: 견적·상담·팀 프로그램 UI]
             |                                     |
             +---------- 공통 API /v1 -------------+
                                    |
                       [건축법령 검색 서비스]
                         |              |
                법제처/공식 데이터     MCP 어댑터
                                    |
                       [AI 해설 오케스트레이터]
                                    |
                무료/유료 모델 공급자 어댑터 (Gemini/Groq/
                   OpenRouter/Ollama/유료 공급자)
                                    |
                    [사용량·비용·예산·정책 서비스]
                                    |
                    [로컬 DB — 추후 팀 DB로 교체 가능]
```

- 프런트엔드가 공급자 API 키나 법령 서비스 인증키를 직접 다루지 않는다.
- 모든 실제 사용량 기록과 **유료 사용 사전 차단은 백엔드가 담당**한다. UI 알림만으로 예산을 관리하지 않는다.
- 장래 팀 프로그램은 동일 서비스 API를 호출해야 하며, React 컴포넌트에 검색/모델/가격 계산 로직을 묻지 않는다.
- 서비스 API 버전 관리 예: `POST /v1/legal/search`, `POST /v1/ai/explain`, `GET /v1/usage/summary`, `GET /v1/providers`. 이는 **미래 계약의 예시**이며 Phase 1에서 서버 엔드포인트 구현은 하지 않는다.
- 모든 API 응답은 성공/실패 상태 및 구조화된 오류와 출처 메타데이터를 가진다. 법령 조회 실패 시 추정한 법적 답변을 성공 응답으로 내보내지 않는다.

## 3. 팀 연동을 고려한 최소 데이터 계약 (지금은 설계/타입만)

- 요청 콘텍스트: `requestId`, `userId`, `organizationId`, `clientApp`, `requestedAt`, `policyId`.
- 개인용 초기에는 서버가 `userId=local-owner`, `organizationId=personal`을 내부적으로 부여해도 된다. **외부 네트워크 공개 시 클라이언트가 임의 전달한 userId/orgId를 신뢰하는 구조는 금지**한다.
- 법령 출처: `sourceId`, `sourceType`(법률/시행령/시행규칙/조례/해석례 등), `lawName`, `article`, `effectiveDate`, `jurisdiction`, `officialUrl`, `retrievedAt`.
- 질문/답변: 질문, 검색된 근거, 쉬운 설명, 주의점, 조회 실패/검증 상태 및 출처를 **서로 분리해 저장 가능한 구조**.
- AI 사용 이벤트: `requestId`, `userId`, `organizationId`, `clientApp`, `provider`, `model`, `tier`, `status`, `inputTokens`, `outputTokens`, `reasoningTokens`, `cacheTokens`, `providerReportedUsage`, `priceVersion`, `estimatedCostUSD`, `fxRate`, `estimatedCostKRW`, `recordedAt`.
- 공급자별 토큰 집계 방식이 다르다. 추론/캐시 토큰이 이미 출력/입력에 포함되는 경우 **중복 과금 계산 금지**. 상세 원시 사용량을 보존하고 공급자별 정규화 규칙을 둔다.
- 개인정보/팀 기록은 향후 사용자·조직별로 논리적으로 분리 가능하도록 설계. **미래 Supabase 연결 시 인증된 사용자 콘텍스트와 RLS 정책을 적용**하며, 단순한 클라이언트 ID 전달만으로 접근을 허용하지 않는다.

## 4. 모델 선택 / 무료 AI / 실제 비용 관리 요구사항

- 공급자별 어댑터 인터페이스를 둔다. 후보: Gemini 무료 티어, Groq 무료 티어, OpenRouter 무료 모델, Ollama 로컬, 승인된 유료 AI. **실제 모델 ID/무료 한도/단가는 당시 공식 제공 조건을 확인하고 설정값으로 관리**한다.
- 무료 티어는 무제한이 아니다. 429 / RPM / TPM / 일간 한도 등을 추적할 수 있게 설계하고, 한도 도달 시 다른 무료 모델 또는 명시적인 유료 전환 안내.
- **무료에서 유료 모델로 자동 전환 금지**. 유료 호출은 사용자가 선택/승인한 경우에만 허용한다.
- 법령 **원문 검색만 수행하면 AI 호출 0회/AI 비용 0원**. AI 해설을 요청한 경우만 과금 토큰이 생길 수 있다.
- 실제 AI 응답의 토큰 메타데이터로 가격을 추정해 표시한다. 가격표에는 `provider/model/tier`, 입력·출력·캐시·도구 단가, 통화, 발효일, 출처, 갱신일을 둔다.
- API 사용량 또는 단가를 확인하지 못하면 **'추정 불가' 또는 '추정치'**라고 표시하며 임의로 0원 처리하지 않는다. 실제 공급자 청구액과 다를 수 있다고 명시한다.
- 요금 표시: **요청 1회 금액 / 입력·출력 토큰 / 모델 / 일간·월간 합계 / 사용자·조직·앱별 집계 가능 구조**.
- 개인용 기본 예산: 월 10,000원(설정 변경 가능). **50% 안내, 80% 경고, 100% 차단**. Asia/Seoul 기준 월간 집계.
- 유료 요청 전에 예상 최대 비용(입력량·최대 출력량·부가 도구비)을 산정해 **예약/사전 차단**, 응답 후 실제 금액으로 정산. 동시 요청 시 예약금액의 원자적 처리, 중복 `requestId`/재시도 정산 중복 방지(향후 실제 백엔드 구현 시).
- 공급자 자체의 과금 제한도 별도 사용하도록 안내. 앱 차단만으로 공급자 청구액을 100% 보증한다고 표시하지 않는다.
- 비용 경고는 같은 임계치에 대해 중복 알림을 남발하지 않고, 월간 리셋 시 초기화한다.
- 팀 확장 시에는 **사용자별 예산 + 조직 전체 예산 + 모델 접근 권한**을 함께 적용할 수 있게 정책 계층을 마련하되, **현재는 관리 화면/실제 팀 관리 기능 구현 금지**.

## 5. 개인정보 및 법령 정확도 정책

- 현장 주소, 건축주 이름, 전화번호, 계약서, 견적서 등 민감한 업무 정보를 무료 클라우드 모델에 그대로 전송하지 않는다. 마스킹/전송 경고/로컬 Ollama 사용 옵션을 설계한다.
- 무료 모델의 데이터 이용 조건 및 상업/업무 사용 정책은 공급자별로 확인하고 설정에 명시한다. 무료 = 비공개 보장이라고 가정하지 않는다.
- 법률 답변은 **공식 자료 조회 → 법령·시행일·지역/조례 적용 범위 확인 → AI 쉬운 설명**의 순서로 처리한다.
- 법률, 시행령, 조례, 유권해석, 참고자료를 **출처 종류별로 구분**한다. 해석례는 법령 원문과 동일한 효력이라고 쓰지 않는다.
- 법령 출처 검증 실패, 해당 필지·지역 정보 미확인, 법령 시행일 불명확 시 '**확인 필요**'로 표기하고 단정하지 않는다.
- 건폐율/용적률은 법정 상한과 실제 대지에 적용 가능한 수치를 명확히 구분한다. 계산기 UI에서 시연·단순 계산임을 표시한다.
- 검색 답변 캐시에는 법령 버전/시행일/조례 지역 등 조건을 포함하고, 자료 개정 시 무효화할 수 있게 설계한다.

## 6. 단계별 개발 범위 — Phase 간 자동 진행 금지

### Phase 1. **지금 실행: Apple UI의 정확한 React 이식 (Sonnet)**

1. `archilaw-apple-budget-ui.html`을 최종 시각 디자인 원본으로 React + Vite + TypeScript 신규 프로젝트를 만든다.
2. 색상, 폰트, 크기, 그림자, 여백, 컴포넌트 순서, PC/모바일/다크 모드를 **임의로 변경하지 않는다**. 최신 예산 관리 패널과 모델 선택기를 포함한다.
3. 질문 입력/추천 질문/예시 답변 탭/북마크/히스토리/건폐율 계산/복사/라이트·다크 전환 등 기존 시연 동작을 전부 유지한다.
4. `ModelSelector`, `UsageMonitor`, `BudgetSettings`, `BudgetAlert` 컴포넌트를 분리한다.
5. 추후 공통 백엔드 연결을 위한 `LegalSearchClient`, `AIProviderClient`, `UsageClient` 등의 **TypeScript 인터페이스와 Mock 어댑터**만 정의한다. UI가 공급자 SDK를 직접 호출하지 않게 만든다.
6. 기존 시연 자료와 샘플 토큰·비용은 명확히 '**샘플/데모**'라고 표시. 실제 사용료 청구·법령 API·MCP·유료 모델 호출·로그인·팀 대시보드 **구현 금지**.
7. 검증: PC 1536×1030, 모바일 390×844, 다크 모드 캡처를 원본과 비교. 기능 동작, 콘솔 오류, 타입체크, 빌드, 모바일 가로 스크롤 점검.
8. 완료 시 산출물: 파일 구조, 화면 비교 캡처, 테스트 결과, 향후 API 경계 인터페이스, 변경 사항, 미구현 항목/위험. **사용자 승인 전 Phase 2 진행 금지**.

### Phase 2. 공식 법령 API·MCP + 공통 서비스 기반 (Sonnet)

공식 법령 API 인증·검색·조문 원문/시행일 검증, MCP 어댑터, 공통 `/v1` API의 최소 엔드포인트. 개인 로컬 모드로 작동시키되 미래 팀 프로그램에 재사용 가능하도록 구현. 실제 API 한도와 라이선스 확인 후 진행.

### Phase 3. AI 해설 + 무료/유료 모델·토큰 집계 (Sonnet, 필요시 Opus 검토)

검색 근거에 제한된 AI 해설, 공급자 어댑터, 사용량 정규화·추정 비용, 무료 한도 대응. 예산 사전 차단 및 유료 자동 전환 금지. 법령 오류/출처 누락 검증 테스트.

### Phase 4. 지자체 조례·해석례·지역 검색 (Sonnet)

지자체 적용 범위, 조례/해석례 구분, 현행 시행일 확인. 필지 데이터 API의 실제 제공 여부를 확인하기 전 자동 확정하지 않는다.

### Phase 5. 계산·북마크·운영 편의 완성 (Sonnet)

건폐율/용적률 계산 확장, 검색 이력/북마크의 실제 저장, 비용 및 사용량 기록. 개인용 중심으로 완성.

### Phase 6. 통합 검증·보안·배포 (Sonnet, 필요시 Opus 검토)

원문·출처 정확도, 예산 초과 차단, 무료 한도 실패 시나리오, 공급자별 정산, 로컬 운영, 팀 연동용 API 계약 테스트. 팀용 배포·SSO·RLS 활성화는 별도 후속 프로젝트로 분리.

## 7. 모델 운용 규칙

- **Phase 1은 Sonnet**. 현재 Opus 사용 불필요.
- Phase 2~3에서 법령 출처/검색 아키텍처 판단이 난해하거나 Sonnet이 동일한 설계 문제를 반복 해결하지 못할 때 **Opus에 한정된 설계 검토**를 제안할 수 있다.
- Phase 6에서 중대한 법령 정확도/권한/비용 정산 구조를 검증할 때 필요한 범위만 Opus 검토를 요청한다.
- Opus 사용 시 사유·예상 작업 범위·Sonnet 복귀 시점을 **먼저 보고**하고 사용자 승인 없이 전환하지 않는다.

## 8. 이번 실행 지시 — 먼저 Phase 1만 수행
